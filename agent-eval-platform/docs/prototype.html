下线理由为什么建议砍掉 Agent-as-Judge

评判官本身能多步推理、挂工具、查外部事实——那就是另一个 Agent 系统，等于要再做一个被测对象来评被测对象。更要命的是它不可复现：同一条轨迹两次评分可能不同，评测结论就失去了仲裁力。上表 B-05 的 L-01 只有 78%，也确实没达到 ≥90% 的门禁。用普通 LLM-as-Judge 加 rubric 校准即可。

接入中心

统一走 LoongSuite 接入 · 按智能体形态选三条通道之一 · 全部以 OTLP 上报到 Collector :4318 或自研网关 /api/otlp/v1/traces

取舍标记已开启本页判定 必做 · 保留，但接入方式改为 不自研探针——LoongSuite 是 Apache 开源，这层可以不写

① LoongSuite Python Agent

适用：AgentScope 等 Python 智能体应用

用 loongsuite-instrument 包裹原启动命令，业务代码零改动。官方已提供 loongsuite-instrumentation-agentscope 插件。

② LoongSuite Pilot

适用：OpenCode · Hermes Agent 等本地 Coding CLI

装在开发机上的本地采集器，自动发现已装的 coding agent 并注入插件。OpenCode 走 plugin injection，Hermes 走 native directory plugin，两者都在官方支持清单里。

③ OTLP 直推（兜底）

适用：CodeBuddy 及其他 Pilot 未覆盖的工具

工具自身支持 OTel 时按其文档指向本平台；也可直接打自研网关，带 App Key 即可，不必部署 Collector。

口径提醒CodeBuddy 不在 Pilot 官方清单里

Pilot 的支持清单里有 WorkBuddy（腾讯的 AI 办公工作站），没有 CodeBuddy（腾讯的 AI 代码编辑器）。两者同源但不是一个产品，不能当成 CodeBuddy 已被支持。好在 CodeBuddy Code 自身支持按 OTel 规范推 trace 到自有 Collector，所以走通道 ③ 是干净的——但要按它自己的环境变量文档配，不是按 Pilot 的。

AgentScope 智能体接入在智能体的运行环境 / 容器镜像内执行

# 1) 安装发行版与插桩插件 pip install "loongsuite-distro[otlp]" loongsuite-bootstrap -a install --latest --auto-detect # 只需 AgentScope 时也可单装：pip install loongsuite-instrumentation-agentscope # 2) 指向本平台的 OTLP 网关 export OTEL_SERVICE_NAME=case-gen-agent export OTEL_TRACES_EXPORTER=otlp export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf export OTEL_EXPORTER_OTLP_ENDPOINT=http://agenteval.internal:4318 # 3) 包裹原启动命令，业务代码一行不改 loongsuite-instrument python main.py

OpenCode / Hermes Agent 接入每台开发机装一次

# 1) 安装 Pilot（Linux / macOS） curl -fsSL https://loongcollector-community-edition.oss-cn-shanghai.aliyuncs.com/loongsuite-pilot/installer.sh \ -o /tmp/loongsuite-pilot-installer.sh && bash /tmp/loongsuite-pilot-installer.sh install # 2) 配 OTLP Trace 导出（~/.loongsuite-pilot/config.json 或环境变量） # Pilot 自动发现本机已装的 agent 并注入对应插件： # OpenCode → plugin injection # Hermes Agent → native directory plugin # 3) 校验接入与用量 loongsuite-pilot status loongsuite-pilot token-usage

为什么 Coding CLI 必须走 Pilot，而不是发个 SDK 让人接

OpenCode、Hermes 这类工具跑在研发同学自己的机器上，你既没有它们的进程入口，也不可能要求上千号人改启动脚本。Pilot 的做法是装成常驻本地采集器，发现哪些 agent 在用就注入哪些钩子，把活动归一成同一套 GenAI 事件模式再导出——这正对上「接入摩擦是内部平台第一死因」那条判断。

关于这份原型

画的是 agent-eval-platform 应用取舍结论之后的目标形态，不是重新设计。13 个屏全部可点。配色、字号、间距、组件形态全部取自工程现有的 frontend/src/style.css 与 Element Plus 观感：底 #f6f7f9、主色 #1f56e8、侧栏 236px、顶栏 54px、卡片 12px 圆角无阴影。字段名、表格列、页面副标题都来自现有页面，没有自己编。

点顶栏的 取舍标记 开关，可以把上一轮的判决叠到界面上：紫色是新增，琥珀色是建议下线。

新增

成本与配额　后端 services/budget.py 已经实现了 JudgeBudget 日额度台账、按模型定价（JUDGE_PRICES）和 auto_pause_budget_tasks 超额自动暂停，但前端一个入口都没有——今天只能从告警里间接看到它生效了。原型里这一页把已有能力直接暴露出来，是投入产出比最高的一块。

新增

操作审计　/api/system/audits 已存在，但埋在「系统管理」的第三个页签里。1000 人规模下改 rubric、改金标准、重跑任务这三类操作会直接影响发布决策，提为一级导航并单独标高风险。

新增

指标库　评估过了，结论是做，但只做只读字典。现在指标编号（C-03、D-02）是以字符串形式散在评估器名字里的，写错没人拦——这跟 PRD §3.3 排除方案二的理由完全同构。成本是一张表 + evaluator 加一个 metric_code 外键，换来的是失败归因能落到「层 × 柱」格子里，以及那张覆盖度矩阵。

改造

接入中心改走 LoongSuite　三条通道对应部门四种智能体：AgentScope 走 Python Agent（loongsuite-instrument 包裹启动、代码零改动），OpenCode 与 Hermes Agent 走 Pilot（装在开发机上自动注入插件，两者都在官方支持清单里），CodeBuddy 走 OTLP 直推。命令全部取自官方仓库。

建议下线

Agent-as-Judge 评估器类型　现有实现里已经有（Evaluators.vue 副标题列了四类，budget.py 也按 type in ["llm","agent"] 处理）。砍它的理由不是做不出来，是评判官不可复现会让评测结论失去仲裁力。

建议下线

在线持续评估任务　Tasks.vue 现有「在线任务 / 离线任务」双页签。在线那半是运维范式，与本平台的离线门禁范式混在一起，会让「这个分数能不能拦发布」说不清。原型把离线放到了第一页签。

保留

轨迹详情的证据层　原型在「评估结果」页签里补了一块现有实现没有的东西：把打分公式和三个试次口径显式画出来（task_score = s_safety × (α·s_completion + β·s_robustness)，α=0.8 / β=0.2 / τ=0.75 / k=3，同时报 Average、pass@k、pass^k）。这些规则今天只活在文档里，界面上看不见就等于没有约束力。

还需要你定的两件事

冲突

工程里在用 ClickHouse，PRD §5.3 写的是「为什么不引 ClickHouse」。代码已经有 services/clickhouse_store.py 和 backfill_clickhouse.py，仪表盘也优先走 ClickHouse 聚合。这跟 PRD「部署组件 5 个」的结论不一致，两边得对齐一个——原型没有替你选，成本页的口径两种存储都成立。

待确认

CodeBuddy 的接入路径要实测。LoongSuite Pilot 官方支持清单里是 WorkBuddy（腾讯 AI 办公工作站），不是 CodeBuddy（腾讯 AI 代码编辑器）——同源但不是一个产品，别当成已支持。CodeBuddy Code 自身支持按 OTel 规范推 trace 到自有 Collector，原型按这条路画的，但需要实测一次，确认字段能被网关正确归一。

待定

下线不等于删代码。Agent-as-Judge 和在线任务如果已经有人在用，建议先在界面上标为「不再演进」并停止新建入口，跑满一个回归周期再决定是否摘除。原型里我用条纹和琥珀标记表达的就是这个中间态，不是直接删掉。

单文件、零外部依赖（仅 Google Fonts 的 Inter 与 JetBrains Mono），可直接另存为 .html 双击打开。页面刻意只做浅色主题，与工程现状一致。所有数字均为示意数据，真实取值来自 /api/dashboard、/api/regression/runs 等既有接口。
