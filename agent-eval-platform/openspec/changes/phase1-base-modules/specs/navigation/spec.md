## Purpose

定义平台左侧导航的一级分组与二级菜单的包含关系、路由映射与高亮规则，并规定角色对写操作的可见性。导航结构是用户理解整个平台的入口，因此它本身是一项需要被固定下来的契约。

## ADDED Requirements

### Requirement: 一级分组与二级菜单的包含关系

系统 SHALL 按以下包含关系呈现左侧导航，一级分组仅作为标题不可点击，二级菜单为可点击的路由入口：

| 一级分组 | 二级菜单 | 路由 |
|---|---|---|
| 总览 | 仪表盘 | `/dashboard` |
| 观测与审计 | 接入中心 | `/access` |
| 观测与审计 | AI Agent 可观测 | `/traces` |
| 评估与实验 | 指标库 | `/metrics` |
| 评估与实验 | 评估器 | `/evaluators` |
| 评估与实验 | 评估任务 | `/tasks` |
| 评估与实验 | Bad Case 管理 | `/badcases` |
| 数据中心 | 轨迹库 / 数据集 | `/datacenter` |
| 持续优化 | 实验与回归 | `/regression` |
| 系统管理 | 成员与权限 | `/system` |
| 系统管理 | 操作审计 | `/audit` |

一期范围内 SHALL NOT 出现「成本与配额」二级菜单。「通知中心」保持现状，不在本次结构调整范围内。

#### Scenario: 数据中心只呈现一个二级菜单

- **WHEN** 用户查看左侧导航的「数据中心」分组
- **THEN** 该分组下只有一个二级菜单「轨迹库 / 数据集」
- **AND** 点击后进入同一页面，页内以页签切换轨迹库与数据集

#### Scenario: 操作审计是独立的二级菜单

- **WHEN** 用户查看「系统管理」分组
- **THEN** 该分组下有「成员与权限」与「操作审计」两个二级菜单
- **AND** 进入「成员与权限」后，页内 SHALL NOT 出现「审计日志」页签

### Requirement: 当前位置高亮

系统 SHALL 高亮与当前路由对应的二级菜单。对于从列表下钻进入的详情页，SHALL 继续高亮其所属的列表菜单。

#### Scenario: 列表页高亮自身

- **WHEN** 用户停留在 `/traces`
- **THEN** 「AI Agent 可观测」处于高亮态，且同一时刻只有它一项高亮

#### Scenario: 详情页高亮所属列表

- **WHEN** 用户从 Trace 列表下钻进入 `/traces/:id`
- **THEN** 「AI Agent 可观测」仍保持高亮
- **AND** 页面提供返回列表的入口

### Requirement: 工作空间切换与数据隔离

系统 SHALL 在顶栏提供工作空间切换入口，切换后按新空间重新加载数据。用户 SHALL NOT 看到未加入空间的数据。

#### Scenario: 切换工作空间

- **WHEN** 用户在顶栏切换到另一个已加入的工作空间
- **THEN** 界面提示已切换，且各页数据按新空间重新加载

#### Scenario: 无权访问的空间

- **WHEN** 请求携带的工作空间标识不在用户的成员关系内
- **THEN** 系统拒绝该请求并返回无权访问

### Requirement: 角色对写操作的可见性

系统 SHALL 按当前用户在该工作空间内的角色控制写操作控件：只读角色的写操作控件 MUST 置灰且不可触发。

#### Scenario: 只读角色

- **WHEN** 只读角色用户进入任一模块
- **THEN** 新建、编辑、删除、复核、发布类控件全部置灰
- **AND** 查询、筛选、排序、下钻等读操作不受限制

#### Scenario: 开发与管理员角色

- **WHEN** 开发或管理员角色用户进入模块
- **THEN** 其权限范围内的写操作控件可用
- **AND** 仅管理员可见成员管理与配额调整类操作
