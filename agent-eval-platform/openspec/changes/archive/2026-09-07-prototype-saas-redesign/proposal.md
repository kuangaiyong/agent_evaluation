## Why

现有 `docs/prototype.html`（15 屏）是一期基线，它解决的是「有哪些屏、每屏有哪些字段」，但有三个问题现在必须一起解掉：

1. **信息架构不完整**。刚完成的 [AgentLoop 产品调研](../../../产品调研/AgentLoop/README.md)（12 模块 / 26 子页 / 21 内置评估器实测）暴露出我们缺了整块能力：快速启动引导、风险审计、Agent 资产（Prompt/Skill 版本化）、上下文工程（经验库/记忆库）、数据加工 Pipeline。这些不是锦上添花 —— 「轨迹清洗成数据集」这条数据飞轮断了，评测集就只能靠人工攒。
2. **撑不住 1000 人规模**。当前原型是单工作区模型，没有空间隔离、角色权限、配额约束。1000 人多业务线共用一个区，评测任务会互相干扰，成本也无法归属。
3. **视觉停留在「能看」而非「能用」**。现有原型是功能线框，缺少成熟 SaaS 产品的信息层级与状态表达，拿给部门推广时说服力不足。

一次性重做原型，把信息架构、规模模型、视觉体系三件事对齐到位，仍然遵守「先改原型、再改代码」的既定顺序。

## What Changes

产出一份全新的高保真单文件原型，**直接替换 `docs/prototype.html`**（G1 已确认，代价见下文 Impact），并同步重写 `docs/prototype.smoke.js`。

### 品牌与命名

- 全局品牌 **TAgentEval**，原型内不出现 `AgentLoop` 字样
- 「数据中心」更名为 **数据魔方**
- **不依赖阿里云商业服务**（需云账号与付费的那些）：SLS、云监控 2.0/CMS、MSE AI 治理中心、ARMS、AgentSpace、AI 积分计费 —— 分别替换为自建存储、自建仪表盘与告警、自建资产托管、自建 OTLP 采集网关 + 接入 Token、工作空间/项目、自定义配额单位
- **LoongSuite 保留并作为主线技术栈**（用户裁定）：它是 Apache 开源、可自部署的探针套件，是我们选定的**智能体无侵入接入**方案，也与 phase1 已实现的接入中心口径一致。OpenTelemetry / OTLP 同样保留
- 被观测方的框架名（LangChain/LangGraph、AgentScope、Dify、Claude Code、Codex 等）照常出现 —— 它们是接入对象，不是我们的云依赖

### 菜单结构（一级 / 二级）

在 phase1 已实现结构之上扩展，新增项标 **NEW**：

| 一级 | 二级 |
|---|---|
| 总览 | 工作台 · **快速启动 NEW** |
| 观测与接入 | 接入中心 · 链路观测 · **仪表盘 NEW** |
| 评测与实验 | 评估器（**改造**） · 评估任务 · **分析洞察 NEW** · Bad Case 库 · 实验与回归 |
| **数据魔方**（原数据中心） | 轨迹库 · 数据集 · **数据加工 NEW** |
| **持续优化 NEW** | **Agent 资产 NEW** · **经验与记忆 NEW** |
| 治理与系统 | **风险审计 NEW** · 操作审计 · **成本与配额 NEW** · 空间与成员 · **通知中心 NEW** |

共 20 个导航项 + 1 个下钻屏（链路详情），`[data-screen]` 容器合计 21 个。相比现有 15 屏 / 14 个导航项：导航项 14 → 20（净增 6），其中「数据中心」1 屏拆为「数据魔方」3 屏、新增 5 屏、删除「指标字典」1 屏。

### 接入中心的通道设计

以 **LoongSuite 无侵入接入**为主线，按被接入对象的形态分四条通道（前三条继承 phase1 已实现口径，第四条为本次新增）：

| 通道 | 技术 | 适用对象 | 侵入性 |
|---|---|---|---|
| **Python Agent** | LoongSuite Python 探针，改启动命令即可 | 应用内 Agent：LangChain / LangGraph / AgentScope / OpenAI SDK 等 | 无需改代码 |
| **Pilot** | LoongSuite Pilot 本地采集客户端，一机装一次 | 本地 Coding Agent：Claude Code / Codex / OpenCode / Cursor 等 | 无需改代码 |
| **OTLP 直推** | OpenTelemetry SDK 标准协议 | 自研 Agent、无探针覆盖的框架 | 需少量埋点 |
| **eBPF 无侵入 NEW** | 主机/容器级内核态采集 | 无法改启动方式的存量服务 | 零改动 |

四条通道统一上报到**自建 OTLP 采集网关**（内网域名 + 接入 Token），不经任何云厂商端点。应用列表带「接入通道」列，允许同一空间内多通道混用。

### 评估能力来源：DeepEval

用户裁定 **92 条指标字典不再需要，改由开源库 DeepEval 预置评估器**。因此：

- **删除「指标字典」屏**，其职能由「评估器」屏承接
- 评估器分两类：**DeepEval 预置**（RAG 5 个 · Agentic 3 个 · 多轮会话 4 个 · 安全与质量 4 个）与**自定义**（`GEval` 自然语言 criteria、`DAGMetric` 决策树式确定性评分）
- 评估器配置表单按 DeepEval 真实参数设计：`threshold`（我们取 τ=0.75，非 DeepEval 默认 0.5）、`model`、`include_reason`、`strict_mode`、`async_mode`、`verbose_mode`
- 新增「**分析洞察**」屏承接评分分布、归一化均分、低分样本下钻（原 AgentLoop `explorer` 能力）

打分公式与 α/β/τ/k、三口径报告**保持不变** —— 它们是聚合与判定层口径，与评估器由谁提供无关。三个分量（`s_safety` / `s_completion` / `s_robustness`）与 DeepEval 评估器的映射关系在 design 阶段提出，标为待确认。

### 规模模型（1000 人）

- 顶部**空间切换器**，资源按工作空间隔离
- 四类角色：管理员 / 测试开发 / 测试工程师 / 只读，角色决定按钮可见性与操作权限
- 空间级**评测配额**与用量看板，超额阻断新任务

### 视觉体系

用 `ui-ux-pro-max` skill 做设计决策（配色 / 字体配对 / 组件规范 / 图表类型）。调性取自用户指定的参考页：靛紫主色、DM Sans、大圆角、白卡片轻阴影、疏朗留白、胶囊徽章、语义状态色。支持明暗双主题。

### 交互要求

必须是**可点可跳的真原型**，而非静态截图拼接：

- 左侧导航切屏、页内页签切换
- 表格行下钻到详情（如轨迹 → 链路详情、评估任务 → 结果分析）
- 按钮触发弹窗/抽屉（新建评估任务、创建评估器、创建数据集等），弹窗内分步表单可前进后退
- 筛选、排序、分页、搜索可实际生效
- 角色切换、空间切换、主题切换即时生效

## 非目标

- **不实现后端**，不改 `backend/`、`frontend/` 任何代码。原型与已实现前端的差异出交付清单，由用户决定何时跟进
- **不改方法论数字**。打分公式 `task_score = s_safety × (α·s_completion + β·s_robustness)`、α=0.8 / β=0.2 / τ=0.75 / k=3（关键链路 5）、Average / pass@k / pass^k 三口径 —— 照抄外层文档，原型只消费不改写
- **不动外层方法论文档**。92 条指标（12 组）仍是文档侧资产，本次只是平台不再消费它；文档是否随之调整由用户后续决定
- **不实现 DeepEval 集成代码**。本次只在原型界面上体现其评估器清单与配置字段
- **不做营销落地页**（G1 已确认只取视觉调性）
- **不做真实数据对接**，演示数据静态内置，页面零网络请求
