## 三个核心设计

**① LLM 网关——让"轨迹完整"不依赖被测方自觉。**
被测智能体不会为你的平台改代码，claude code、codex 更不会。但它们都要调模型。把模型调用收敛成唯一出口，用**试次临时凭证**把每一次调用精确归属到试次，就能在智能体零埋点的前提下拿到完整轨迹。副产品：真实密钥不下发、成本能算到每个试次、二期故障注入有现成拦截点。

**② 轨迹分层存储——MySQL 存能查的，对象存储存大的。**
技术栈限定 MySQL，而轨迹是高写入、含大文本的树形数据。span 的索引字段进 MySQL，prompt/completion 全文、shell 输出、文件 diff 进对象存储，span 行只存 key。转录本查看器首屏只拉骨架，点开某条 span 才拉全文。**因此首期不需要 ClickHouse**——按估算首年索引 < 30 GB。

**③ 不可信执行区只有一个出口。**
容器默认拒绝出网，只放行 LLM 网关与平台回调。非 root、无 capabilities、只读根文件系统、资源硬限。四类智能体形态里，**AI 编程工具 CLI**（opencode / claude code / codex）会执行任意 shell，是隔离难度的天花板，也是选容器化的直接原因。

## 四类智能体形态

| 形态 | 隔离难度 | 轨迹从哪来 |
|---|---|---|
| ① 配置式（提示词+模型+工具） | 低 | 平台自己产生 |
| ② Python 代码包 | 中 | LLM 网关兜底 |
| ③ **AI 编程工具 CLI** | **高** | LLM 网关为主 + 会话日志适配器 + shell 审计 |
| ④ 注册远程服务 | 不适用 | 靠对方埋点，**标注「环境不可控」** |

## 诚实的部分

架构文档 §11 与 §15 明确写了**做不到的事**，不粉饰：

- **容器逃逸 0day 防不住**，缓解是执行节点独立池限制爆炸半径
- **shell 审计能被绕过**（直接 `subprocess` 调二进制不经包装 shell），它是取证辅助不是安全边界
- **flash + pro 两档不构成供应商冗余**——同供应商、同端点、同一把 key
- **若最终无 K8s**，降级拓扑需 worker 挂载 `docker.sock`，那是明确的提权路径
