## 这份方案在解决什么

被测智能体读产品需求、技术方案、测试用例、存量自动化工程四件套，通过 codebuddy / opencode 这类 **AI 编程 CLI** 在工作区里干活——读写文件、跑 shell、**自己编译、自己跑测试、跑不过自己改到过**，产出接口自动化与界面自动化测试代码。

这个形态让现成的评测方案失效在一个具体的地方：**「脚本可运行率」「首次通过率」测的是它的自我宣称，不是它的能力**。它交付时那批脚本在它自己的环境里已经是绿的。

所以方案的第一支柱是**独立复现协议**——产物质量只认「评测方在干净容器重跑」的结果，并把**自报与实测之差**升格为一等指标。

## 三件已拍板的事

1. **接口与界面同等深度**。界面侧也做断言有效性度量，但 UI 变异测试业界无成熟方案，改用五手段加权组合 + 动态重归一化。
2. **人工基线窗口已错过**（智能体已在用但没留数据）。改用四条挖掘路径 + 小样本前瞻式配对试验，**所有 ROI 数字标估算、只报区间**。
3. **多语言栈**（Python + JS/TS，部分产品线未统一），变异体镜像流水线做成语言无关。
